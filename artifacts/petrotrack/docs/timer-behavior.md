# Petrotrack timer behavior

## Audit

Petrotrack does not import or call the deprecated native background-timer
module. It was only present as a direct dependency to satisfy an old peer
requirement of the Daily React Native package. The direct dependency is
removed; Daily's native call implementation supplies its own iOS audio and
Android foreground-service behavior.

The app's timers have two categories:

- **Foreground application timers** use `startForegroundTimer` from
  `lib/foreground-timer.ts`. They run on the normal JavaScript timer APIs on
  iOS, Android, and the web preview, stop scheduling while the app is
  backgrounded, and catch up on the next `AppState` `active` event.
  - Business-date rollover checks every 60 seconds and refreshes immediately
    when the app returns to the foreground.
  - Authenticated notification refreshes happen immediately and then every
    5 seconds while the app is active.
  - Authenticated server-version checks run immediately and then every
    3 seconds after each prior check finishes. A foreground transition also
    triggers a check and flushes the report outbox.
- **UI and connection timers** remain ordinary JavaScript timers: the price
  ticker animation advances every 3 seconds, delayed scroll/export cleanup
  callbacks run once, and WebSocket reconnect waits 2 seconds after a close.
  These are not business-critical background jobs and are cancelled with
  their owning screen/effect.

The app does not promise JavaScript polling while the operating system has
suspended it. Server state is authoritative, and foreground revalidation
restores freshness after suspension. Live calls are handled by Daily's native
audio/foreground-service support rather than by an application polling timer.

## Native call backgrounding release check

The Daily Expo config plugin supplies the Android ongoing-call foreground
service and the microphone/camera foreground-service permissions. iOS also
requires the `voip` background mode, which is declared in `app.json`. These
settings only take effect in a native development, preview, or production
build; Expo Go and the web preview cannot validate call continuity.

Run this check with two test accounts in an installed native build, with the
second account acting as the remote participant:

### iOS

1. Start an audio call and confirm both devices can hear each other.
2. Lock the iPhone or background Petrotrack for at least 30 seconds while the
   remote participant continues speaking.
3. Confirm the remote participant still hears the backgrounded iPhone and the
   backgrounded iPhone still receives audio.
4. Return to Petrotrack and confirm the call screen is still open, shows the
   connected participant, and mute/end controls still work.
5. Repeat with a video call if video calling is enabled for the release.

Expected result: audio continues during the short background interval and the
call screen is restored without creating a second call or requiring a manual
rejoin.

### Android

1. Start an audio call and confirm both devices can hear each other.
2. Press Home and leave Petrotrack backgrounded for at least 30 seconds.
3. Confirm the Android ongoing-call notification remains present and the
   remote participant still receives audio.
4. Return to Petrotrack and confirm the call screen reconnects or remains
   connected, the participant list is current, and mute/end controls still
   work.
5. Repeat after briefly switching between Wi-Fi and cellular data when the
   test device permits it.

Expected result: the Daily foreground service keeps the active call alive; a
brief network or process suspension is recovered when Petrotrack returns to
the foreground without creating a duplicate call.

### Workspace verification status

Static verification completed: the Daily patch keeps standard JavaScript
timers, the iOS `voip` mode is present, and the Android manifest generated by
the plugin includes `FOREGROUND_SERVICE`, microphone/camera service types,
and `DailyOngoingMeetingForegroundService`.

Hardware verification is **not run in this workspace**. No iOS or Android
device, emulator, `adb`, `xcrun`, or Maestro runner is attached. Do not treat
the expected results above as evidence of audible continuity; complete both
device checks before release and record the device OS/build, call type,
background duration, and result in the release checklist.
